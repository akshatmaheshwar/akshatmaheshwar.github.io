Languages · Testing04

ToyLang and a hybrid fuzzer

A small programming language written from scratch, plus a bug-finder that combines random mutation with a constraint solver.

# pseudocode: why random mutation struggles
if x == 7331:
  y = 100 / (x - 7331)   # divide by zero

Illustration of the kind of bug it targets. Random mutation almost never guesses 7331; the solver derives it.

  • Lexer, recursive-descent parser, syntax tree and a tree-walking interpreter that records branch and statement coverage.
  • The random fuzzer mutates inputs and keeps only those that reach new code.
  • When random search stalls, Z3 symbolic execution collects the conditions along a path and solves them to produce an input that reaches the unexplored branch.
  • Finds division by zero and assertion failures guarded by exact-match conditions that random mutation almost never hits.

AI · Hackathon08

UQ Agent

A Chrome extension that clicks through the university portal for you. Ask for something in plain English and it finds the page. Built with a team at the UQCS hackathon 2025.

  1. Chat in extension
  2. Local Python server
  3. Vector search
  4. Step plan
  5. Playwright clicks
  • The front end is a React and Vite Chrome extension (Manifest V3) with a chat window. Chat history is stored in Firebase.
  • A small Python server turns the request into steps. It converts the sentence into an embedding and finds the closest stored navigation example in a ChromaDB vector database.
  • Playwright then drives the user's own open Chrome tab through those steps: click, hover, fill, type, select and wait.
  • Portals are awkward, so it waits for the Angular page to settle, matches button labels with fuzzy text matching, caches the selectors it has found, and follows new tabs.
  • Early prototypes asked a local Llama model (through Ollama) to plan the steps directly.
